## 1. 产品概述

### 1.1 产品定义

Noty Desktop 是一款面向 macOS 与 Windows 的本地优先便签软件。它常驻系统状态区，通过贴附在屏幕左侧或右侧的纵向便签 Dock、全局快捷键和快速捕获窗口，让用户在不离开当前工作上下文的情况下快速记录、查看和管理短内容。

Noty 不以“完整知识库”为目标，而专注三个核心价值：

1. **贴在手边**：便签始终可以从屏幕边缘或快捷键快速触达；
2. **安静低扰**：浏览时不打断当前工作，进入编辑时才获取焦点，用完自然收起；
3. **本地可信**：无账号也可完整使用，正文加密存储，数据可导入、导出和备份。

### 1.2 一句话价值主张

> 像桌面家具一样安静，像快捷工具一样及时的跨平台边缘便签。

### 1.3 产品形态

- 一套统一的产品能力、数据模型和视觉语言；
- 分别发布 macOS 与 Windows 桌面安装包；
- 两端共享兼容的导入、导出与备份格式；
- MVP 不提供云同步，不要求两端数据实时一致；
- 平台原生能力允许存在实现差异，但用户行为和数据语义保持一致。

## 2. 产品目标与非目标

### 2.1 MVP 目标

1. 用户可在任意应用中通过全局快捷键完成快速记录；
2. 用户可通过屏幕边缘纵向 Dock 浏览、预览和编辑常用便签；
3. 用户可创建、编辑、自动保存、归档、删除、搜索和恢复便签；
4. macOS 与 Windows 具备一致的核心体验和可交换的数据格式；
5. 应用重启、升级、显示器变化或异常退出后不丢失已保存内容；
6. 正文默认加密落盘，导出和联网边界清晰可见；
7. 两个平台都达到可签名、可安装、可更新的公开发布标准。

### 2.2 MVP 必须交付

- macOS 菜单栏 / Windows 系统托盘常驻入口；
- 单实例运行；
- 左右屏幕边缘纵向 Dock；
- Dock 悬停感应、邻项联动放大、标题展开和快捷操作；
- Dock 整体拖动、左右吸附、垂直位置记忆；
- 便签预览、编辑、新建和自动保存；
- Quick Capture 与可配置全局快捷键；
- 标题、正文、任务、基础 Markdown 和 6 色便签；
- 归档、恢复、删除与 10 秒撤销；
- All Notes / Archive、标题与正文搜索；
- SQLite、本地正文加密、数据库迁移、滚动备份与恢复；
- `.stickies v2`、Markdown、TXT 导入导出；
- Windows 10/11 x64 与受支持的 macOS 版本；
- 多显示器、混合 DPI / Retina、中文与日文 IME、RTL 基础支持；
- 签名安装包和受控更新。

### 2.3 MVP 明确不做

- 账号体系、云同步、多人协作；
- Web、iOS、Android 客户端；
- 提醒、重复提醒和日历；
- 每条便签独立常驻桌面浮窗；
- 将便签绑定到特定网页、文件或应用窗口；
- 文件夹、标签、附件、版本历史；
- OCR、AI 总结或生成能力；
- 插件系统；
- Microsoft Store / Mac App Store 第二渠道；
- Windows ARM64 原生包；
- 直接复制另一平台内部数据库作为迁移方式。

## 3. 目标用户与核心场景

### 3.1 目标用户

**键盘驱动的效率用户**  
频繁在浏览器、IDE 和办公软件之间切换，希望不打开大型笔记应用就记录内容。

**需要临时信息常驻的用户**  
需要随时查看会议要点、待办、代码片段、地址或灵感，但不希望桌面堆满窗口。

**隐私敏感用户**  
不希望注册账号或把工作碎片发送到云端，希望数据留在本机并可自主备份。

**同时使用 Mac 与 Windows 的用户**  
不要求实时同步，但希望两端操作一致，并能通过标准文件安全迁移内容。

### 3.2 核心用户任务

1. 在其他应用中工作时，快速记下一段内容；
2. 将鼠标移到屏幕边缘，找到并预览某条便签；
3. 打开便签，修改标题、正文、任务或 Markdown；
4. 将不再常用的便签归档，并在需要时恢复；
5. 通过关键词找到历史便签；
6. 将全部数据备份，或从另一台 Mac / Windows 设备导入；
7. 在重启、升级和异常退出后继续使用，且内容不丢失。

## 4. 产品原则

1. **捕获优先于组织**：新建和记录必须比分类更快；
2. **Dock 是核心，不是唯一入口**：状态区入口和快捷键必须完整兜底；
3. **预览不抢焦点，编辑才获取焦点**；
4. **原文可靠优先于样式效果**：IME、Undo 和文本无损优先于 Markdown 动画；
5. **正常保存保持安静，保存失败必须可见且可恢复**；
6. **跨平台统一语义，不追求逐像素完全一致**；
7. **本地优先，不等于不能更新**：联网行为必须可解释、可关闭；
8. **不夸大加密**：明确区分正文、元数据、内部备份和明文导出；
9. **迁移不静默丢字段**：支持、转换、跳过和失败都必须展示结果。

## 6. 已冻结的产品决策

| 决策域 | MVP 决策 |
|---|---|
| 平台 | macOS + Windows，共享产品与数据规范 |
| 产品主形态 | 左右屏幕边缘的纵向便签 Dock |
| Dock 数量 | 每次只显示一个主 Dock；召出时定位到目标显示器 |
| Dock 位置 | 可拖动，释放后吸附左侧或右侧；记录每块屏幕的垂直位置与边缘 |
| Dock 展示 | 静止时紧凑堆叠；悬停时当前项和相邻项联动放大并显示标题 |
| 快捷操作 | 在同一便签上持续悬停约 1 秒后显示归档和删除 |
| 阅读与编辑 | 单击便签打开预览卡；点击“编辑”进入编辑器 |
| 标题 | 支持独立标题，建议上限 28 个可见字符；为空时从正文首个非空行派生 |
| 颜色 | MVP 使用 6 色：Lemon、Peach、Rose、Lilac、Sky、Mint |
| 编辑颜色 | 创建时选择；MVP 编辑已有便签时不修改颜色，后续版本再评估 |
| 自动保存 | 停止输入 500–1000ms 后提交，默认 800ms；关闭、退出和更新前强制 flush |
| 删除 | 删除后提供 10 秒撤销；超时后永久删除，MVP 不提供长期废纸篓 |
| 归档 | 从 Dock 移除，进入 Library → Archive，可恢复 |
| 搜索 | All Notes / Archive 分区内搜索标题和解密后的正文，不建立明文正文索引 |
| 焦点 | Dock 浏览和预览不抢焦点；编辑器与 Quick Capture 获取焦点，结束后尽力恢复原窗口 |
| 状态区 | macOS 不显示常规 Dock 图标；Windows Deck 不进入 Alt+Tab 或任务栏 |
| 启动 | 开机启动默认关闭；启用后静默进入状态区，不主动打开编辑器 |
| 置顶 | Dock 始终位于可触达层级；编辑器默认不永久置顶；全屏应用默认不覆盖 |
| 遥测 | 默认无产品遥测；诊断信息仅由用户主动生成和提交 |
| 同步 | MVP 无云同步；跨设备通过导入、导出或备份文件迁移 |

## 7. 核心交互流程

### 7.1 Dock 状态机

```text
Hidden
  ├─ 状态区 / 全局快捷键 → Rest
  └─ Quick Capture 快捷键 → Capture

Rest
  ├─ 指针进入 Dock → Hover Focus
  ├─ 显式隐藏 → Hidden
  └─ 拖动手柄 → Moving

Hover Focus
  ├─ 单击便签 → Preview(noteId)
  ├─ 持续悬停约 1s → Quick Actions(noteId)
  ├─ 指针离开 → Rest
  └─ 拖动手柄 → Moving

Quick Actions
  ├─ 归档 → Archive + Feedback
  ├─ 删除 → Delete + 10s Undo
  ├─ 单击便签 → Preview(noteId)
  └─ 指针离开 → Rest

Preview
  ├─ 编辑 → Editor(noteId)
  ├─ 关闭 / Esc → Rest
  └─ 单击任务 → Toggle Task

Editor
  ├─ 自动保存 → Editor
  ├─ 关闭 / Esc / 外部点击 → Flush → Preview 或 Rest
  └─ 保存失败 → 保留编辑器与草稿

Moving
  ├─ 拖动 → 跟随指针
  └─ 释放 → 吸附左/右边缘 + 记忆位置 → Rest
```

### 7.2 Quick Capture 流程

```text
任意应用
→ 全局快捷键 / 状态区菜单
→ 当前鼠标显示器中央稍上方出现 Capture
→ 输入正文
→ Enter 保存；Shift+Enter 换行
→ 成功后关闭并恢复原前台应用
```

- `Esc`、失焦或重复触发快捷键：取消；
- 空白内容不创建便签；
- 保存失败时窗口不关闭，提供“重试”和“复制内容”；
- 标题由正文首个非空行自动派生；
- 新便签进入活动列表顶部。

## 8. 功能需求

优先级：**P0** 为 MVP 发布阻断，**P1** 为 1.1 优先项，**P2** 为候选增强。

### 8.1 首次启动与引导

#### FR-ONB-001 首次启动（P0）

引导不超过 3 个页面，完成以下任务：

1. 演示 Dock 的悬停、预览和编辑；
2. 选择左侧或右侧，并确认是否启用边缘触发；
3. 展示并测试“显示 Dock”和“Quick Capture”快捷键；
4. 可选导入 `.stickies` 文件；
5. 说明关闭后应用仍驻留状态区，以及如何真正退出；
6. 说明正文加密、元数据明文、兼容导出文件为明文；
7. 询问是否开机启动，默认不启用。

验收：可跳过；跳过后所有功能仍可访问；可从 Help 再次打开。

### 8.2 状态区与进程

#### FR-SYS-001 系统状态区入口（P0）

macOS 使用菜单栏图标，Windows 使用系统托盘图标。

菜单统一包含：

- 显示 / 隐藏 Dock；
- 新建便签；
- Quick Capture；
- All Notes；
- Archive；
- Settings；
- 开机启动开关；
- Quit Noty。

Windows Explorer 重启后须恢复托盘图标；macOS 菜单栏重载或休眠唤醒后须保持可用。

#### FR-PROC-001 单实例（P0）

- 同一用户会话只允许一个应用实例和一个数据库写入者；
- 第二次启动将命令行、文件或 URL 激活参数转交现有实例；
- 不产生重复状态区图标或并发数据库写入。

### 8.3 全局快捷键

#### FR-HOTKEY-001 快捷键（P0）

提供以下动作，安装后给出平台适配的默认组合：

- 显示 / 隐藏 Dock；
- 新建并打开编辑器；
- Quick Capture；
- All Notes；
- Archive。

要求：

- 使用系统级全局快捷键能力，不要求辅助功能权限或管理员权限；
- 设置时即时检测冲突；失败时保留旧组合并显示原因；
- 禁止无修饰键的单字母、数字及平台保留组合；
- 快捷键展示使用平台符号和术语，macOS 使用 `⌘/⌥/⌃/⇧`，Windows 使用 `Ctrl/Alt/Shift/Win`；
- 若系统无法注册默认组合，首次启动必须引导用户重设。

> 默认按键组合在技术原型阶段按两平台分别冻结，不在本 PRD 中强制要求完全相同。

### 8.4 Edge Dock

#### FR-DOCK-001 静止与悬停（P0）

- Dock 纵向贴附左侧或右侧屏幕边缘；
- 静止状态以便签纸片堆叠显示，减少占屏面积；
- 指针靠近时按距离放大当前项，并带动相邻项产生较弱位移和缩放；
- 当前便签显示短标题，超过 6 个可见字符时省略；
- Dock 离开后恢复紧凑状态；
- 支持系统“减少动态效果”，开启后取消弹性、旋转和逐项动画，只保留即时状态切换。

#### FR-DOCK-002 快捷操作（P0）

- 在某一便签上持续悬停约 1 秒，显示归档与删除按钮；
- 鼠标移出后隐藏按钮；
- 操作按钮拥有文字提示、可访问名称和清晰的危险状态；
- 快捷操作不得因 Dock 缩放导致指针意外离开命中区；
- 键盘用户可通过焦点和上下文菜单访问相同操作。

#### FR-DOCK-003 预览（P0）

- 单击便签，在 Dock 内侧打开便签预览卡；
- 显示完整标题、Markdown 渲染正文和任务状态；
- 预览本身不抢走当前前台应用的键盘焦点；
- 任务 checkbox 可直接切换并立即保存；
- 链接仅允许 `http`、`https`、`mailto`；不得自动打开；
- 点击编辑按钮后进入可输入编辑器；
- `Esc` 或关闭按钮关闭预览。

#### FR-DOCK-004 拖动与吸附（P0）

- 鼠标拖动 Dock 手柄可移动整个 Dock；
- 拖动中便签收拢成稳定形态，隐藏快捷操作，避免误触；
- 释放时根据指针所在屏幕的左右半区吸附到最近边缘；
- 保留释放时的垂直位置，并约束在屏幕工作区内；
- 手柄获得键盘焦点后，`Enter` / `Space` 可在左右边缘间切换；
- 拖动开始时关闭预览和编辑器，并先执行保存；保存失败则阻止拖动离开编辑状态。

#### FR-DOCK-005 多显示器（P0）

- 显式召出时按“鼠标所在屏 → 活动窗口所在屏 → 主屏”选择显示器；
- 每块显示器分别记录边缘和垂直比例；
- 不覆盖菜单栏、任务栏、Dock 或安全区；
- 显示器拔除后自动夹回可见工作区；重新接入后恢复合理位置；
- Windows 使用 Per-Monitor V2 DPI；macOS 使用逻辑点和 backing scale；
- 在 100/125/150/200% DPI 与 Retina / 非 Retina 混合环境中，视觉尺寸和命中区保持一致。

#### FR-DOCK-006 容量与排序（P0/P1）

P0：

- Dock 支持滚动查看超出可视区域的便签；
- 新便签置顶，默认按用户顺序持久化；
- 归档后从 Dock 移除。

P1：

- 支持便签拖动排序；
- 必须与 Dock 整体拖动手柄清晰区分；
- 拖动超过约 5 DIP / pt 后才进入排序状态。

### 8.5 新建与编辑

#### FR-EDIT-001 新建便签（P0）

- 从 Dock 新建按钮、状态区菜单或快捷键打开；
- 编辑器包括标题、颜色选择、正文区、Markdown 工具栏和自动保存状态；
- 新建时从 6 色中随机选择默认色，用户可修改；
- 标题可留空；正文首个非空行将派生标题；标题与正文均为空时不创建；
- 明确创建过但之后清空的既有便签允许保留为“未命名便签”。

#### FR-EDIT-002 标题（P0）

- 标题为独立字段；
- 建议输入上限为 28 个 Unicode grapheme cluster；
- 标题为空时，从正文首个非空行去除任务符号和常见 Markdown marker 后派生；
- 导入文件中的显式标题必须保留；
- 标题元数据为明文，首次使用和隐私说明中明确告知。

#### FR-EDIT-003 纯文本编辑核心（P0）

- 正文逻辑存储为 UTF-8 纯文本；
- 富文本粘贴转换为纯文本，并保留换行；
- 支持平台标准复制、粘贴、剪切、全选、撤销、重做和查找；
- 支持 emoji、组合字符和代理对，不得产生损坏字符；
- 支持中文、日文 IME composition，不在组合阶段错误提交或重绘；
- 支持 Automatic / LTR / RTL 文字方向；
- 正文内容和 Undo 栈不得因样式渲染失败而被修改。

#### FR-EDIT-004 自动保存（P0）

- 用户停止输入 500–1000ms 后自动保存，默认 800ms；
- 输入期间不持续显示提示；提交时显示 `Saving…`，成功后短暂显示 `Saved`；
- 关闭预览、关闭编辑器、拖动 Dock、退出应用、系统注销和更新前立即 flush；
- 单次便签保存使用事务，不覆盖上一个有效版本；
- 保存失败时保留当前窗口和内存草稿，显示 `Save failed`，并提供重试和复制内容；
- 正常保存不发送系统通知。

### 8.6 任务与 Markdown

#### FR-TASK-001 内联任务（P0）

- 内部文本使用行首 `☐` / `☑` 表示任务；
- 工具栏可将当前空行或新行转换为任务；
- 点击 checkbox 切换状态；完成项淡化并添加删除线；
- 非空任务行按 Enter 自动续建未完成任务；
- 空任务行按 Enter 或 Backspace 退出任务模式；
- Markdown 导出转换为 `- [ ]` / `- [x]`，导入时反向转换。

#### FR-MD-001 Markdown（P0）

编辑器工具栏提供：

- 任务；
- 标题；
- 粗体；
- 斜体；
- 无序列表；
- 行内代码。

预览支持：

- H1–H3；
- 粗体、斜体、删除线；
- 行内代码；
- 引用、无序列表；
- `http`、`https`、`mailto` 链接；
- 任务列表。

要求：

- Markdown 原文无损存储；
- 普通点击链接不应误触编辑；平台标准修饰键 + 点击打开链接；
- 不执行 HTML、脚本、命令或任意 URL scheme；
- 所见即所得 marker 隐藏不进入 MVP，列为 P1。

### 8.7 归档、删除与恢复

#### FR-NOTE-001 归档（P0）

- 归档后立即从 Dock 移除；
- 进入 Library → Archive；
- 可恢复至活动列表顶部；
- 保留标题、正文、颜色、时间、顺序和文字方向。

#### FR-NOTE-002 删除与撤销（P0）

- 删除提交必须是原子操作，异常退出不得出现 UI 与数据库状态不一致；
- MVP 不提供长期废纸篓。

### 8.8 Library 与搜索

#### FR-LIB-001 Library（P0）

- 提供 All Notes 与 Archive 两个分区；
- 左侧列表显示颜色、标题、修改时间和任务进度；
- 右侧显示预览或编辑详情；
- 支持键盘导航、编辑、归档、恢复和删除；
- Library 是常规应用窗口：进入 Windows Alt+Tab / 任务栏和 macOS App Switcher / Dock 临时活动态。

#### FR-SEARCH-001 搜索（P0）

## 9. 数据需求

### 9.1 核心数据模型

```text
Note
- id: UUIDv7 string（客户端生成，全局唯一）
- title: string
- titleSource: explicit | derived
- body: encrypted blob
- color: lemon | peach | rose | lilac | sky | mint
- createdAt: UTC timestamp（毫秒精度）
- updatedAt: UTC timestamp（毫秒精度）
- archivedAt: nullable UTC timestamp
- deletedAt: nullable UTC timestamp
- sortKey: string（稳定排序键，禁止依赖浮点数）
- textDirection: automatic | ltr | rtl
- revision: unsigned integer（每次业务变更递增）
```

MVP 无 Folder、Tag、Attachment、Account、Workspace、Reminder 实体。`revision`、删除墓碑和稳定排序键从首版保留，以避免未来增加账号与云同步时重写核心表。MVP 本地删除在撤销期结束后可由清理任务物理删除；启用同步后则必须保留服务端确认前的 tombstone。

### 9.2 存储

- 每个平台使用用户级应用数据目录；
- 使用 SQLite，启用 WAL，保持单写者；
- 从首版启用 schema 版本和事务化 migration；
- 数据库、设置、备份和日志分离；
- 日志禁止包含正文、标题、搜索词、剪贴板内容及完整用户路径；
- 相同领域 schema 和序列化契约适用于两端，但内部数据库文件不作为跨平台交换接口；
- SQLite 与未来 PostgreSQL 只要求**逻辑模型和 API DTO 可映射**，不追求 DDL、类型或数据库文件直接兼容；
- 所有写入通过 Rust Repository / Service 层完成，Vue 不直接访问 SQLite；
- 时间通过 UTC RFC 3339 或 Unix 毫秒在协议层传输，禁止依赖数据库本地时区；
- 枚举在协议层使用稳定字符串值；金额、排序和版本等需要确定性的字段禁止使用浮点语义。

### 9.3 加密边界

- 每次安装 / 用户生成随机 256-bit 数据密钥；
- 正文使用经过审计的 AEAD 算法加密；
- 数据密钥由平台安全存储保护：macOS Keychain、Windows DPAPI 或等价能力；
- 标题、颜色、时间、归档、排序和文字方向为明文元数据；
- 内部数据库和自动备份默认只能在同一系统用户上下文中解密；
- 跨设备恢复使用带用户密码的 `.notybackup`；
- `.stickies`、Markdown、TXT 是明文格式，导出前必须提示。

### 9.4 自动备份与恢复

- 每日首次成功写入后最多创建一次滚动备份；
- 应用升级或 schema migration 前强制备份；
- 保留最近 7 份或 30 天，以先达到者为准；
- 数据库校验失败时不得覆盖最后有效备份；
- 提供“自动恢复”“选择备份”“导出诊断”入口；
- 磁盘满时暂停非必要备份，保留编辑草稿并提示释放空间；
- 旧版本不得写入更高 schema 数据库。

## 10. 平台一致性与差异

| 能力 | macOS | Windows | 统一要求 |
|---|---|---|---|
| 常驻入口 | Menu Bar | System Tray | 菜单语义一致 |
| 应用切换器 | 非编辑态不出现常规 Dock 图标 | Deck 不进入 Alt+Tab / 任务栏 | Library / Settings 为常规窗口 |
| 全局快捷键 | 平台原生注册 | `RegisterHotKey` 或等价能力 | 不使用侵入式键盘监听 |

平台差异不得改变以下用户语义：便签字段、自动保存、任务、Markdown、归档、删除、搜索、导入导出、备份和错误处理。

## 11. 非功能需求

### 11.1 性能（P0）

| 项目 | 目标 |
|---|---:|
| 冷启动至状态区可用 | p95 ≤ 1.5s |
| 驻留时快捷键至可输入 | p95 ≤ 150ms |
| Dock 指针反馈 | 首帧 ≤ 50ms |
| 搜索刷新（500 条、平均 2KB） | p95 ≤ 100ms |
| 自动保存 | 停止输入后默认 800ms 开始提交 |
| 空闲 CPU | p95 < 1% |
| 空闲工作集 | 技术原型后冻结，建议 ≤ 150MB |
| 动画 | 60Hz 屏幕无持续明显掉帧 |

压力数据集：10,000 条便签、平均正文 10KB。最终容量上限在技术原型后冻结。

### 11.2 可靠性（P0）

- 停止输入并完成保存后强杀进程，重启内容完整；
- 创建、修改、归档、恢复、删除、重启连续 100 轮，无重复 ID 或内容丢失；
- 单实例压力测试始终只有一个数据库写入者；
- schema migration 失败可恢复升级前备份；
- 休眠唤醒、屏幕变化、状态区重载后入口恢复；
- 任何保存失败都不得静默关闭编辑器。

### 11.3 兼容性（P0）

**Windows**

- Windows 10 22H2 x64；
- Windows 11 当前受支持版本 x64；
- 标准用户账户，不要求管理员权限；
- 100/125/150/200% 混合 DPI；
- 任务栏四边及自动隐藏。

**macOS**

- 最低版本在技术选型后冻结，至少覆盖当前版本及前两个主要版本；
- Apple Silicon 原生；Intel 支持与否在框架原型和用户规模验证后冻结；
- Retina / 非 Retina、菜单栏和 Dock 自动隐藏。

**共同矩阵**

- 单屏、双屏、主副屏切换和热插拔；
- 中文、英文、日文 IME；
- Arabic / Hebrew 基础 RTL；
- 深色、浅色、高对比度 / 增强对比度、减少动画。

### 11.4 可访问性（P0）

- 所有核心动作可仅用键盘完成；
- Dock、编辑器、Library 和 Settings 提供可访问名称、角色和状态；
- 焦点顺序可预测，焦点样式清晰；
- 不以颜色作为唯一状态表达；
- 支持系统文本缩放、对比度和减少动画设置；
- VoiceOver、Narrator / NVDA 可读取标题、任务状态、按钮和搜索结果；
- Dock 不进入应用切换器时，状态区和快捷键仍提供完整入口。

### 11.5 安全与隐私（P0）

- 不加载远程便签内容、远程脚本或未验证插件；
- URL 和导入文件全部按不可信输入处理；
- 仅允许白名单链接协议；
- 正式安装包与更新包必须签名；
- 更新仅接受同一发布者且版本递增的有效签名包；
- 依赖锁定版本并生成第三方许可清单；
- 锁屏、切换用户或远程桌面断开时隐藏预览和编辑器；
- 诊断包默认移除标题、正文、搜索词、剪贴板和个人路径。

### 11.6 网络与遥测（P0）

MVP 允许的网络行为仅包括：

- 用户可关闭的更新检查；
- 用户主动打开帮助或发布说明网页；
- 用户主动提交诊断或反馈。

不得发送正文、标题、搜索词、剪贴板或导入文件内容。未来若增加遥测，必须单独更新隐私说明并获得用户明确选择。

## 12. 安装、更新与卸载

### 12.1 分发

- macOS：签名并公证的直接下载包；
- Windows：签名安装包，具体使用 MSIX 或其他方式由技术选型验证决定；
- MVP 每个平台只维护一条正式分发和更新链路；
- 首版发布前固定应用标识、Publisher / Team Identity、URL Scheme 和证书策略。

### 12.2 更新

- 默认每日检查，可关闭；
- 不携带笔记或设备内容；
- 不在用户输入时强制退出；
- 安装前 flush 并创建备份；
- migration 失败时恢复备份并维持旧版可运行；
- 至少测试从前两个正式版本升级到当前版本；
- 禁止低版本直接写入高版本数据库。

### 12.3 卸载与数据

- Help 和卸载说明明确数据保留或删除行为；
- 设置中提供“导出完整备份”和“删除所有本地数据”；
- 删除所有数据需二次确认；
- 删除范围包括数据库、密钥、备份、日志和启动项；
- 若平台卸载会自动删除应用数据，卸载前必须明确提示先导出。

## 13. 核心验收场景

### AC-01 首次使用

1. 标准用户安装并启动；
2. 完成或跳过引导；
3. 状态区图标可用；
4. 用户通过快捷键创建便签；
5. 编辑后关闭并重启；
6. 标题、正文、颜色和顺序恢复；
7. 未获同意时开机启动保持关闭。

### AC-02 Dock 核心体验

1. Dock 位于屏幕边缘并紧凑堆叠；
2. 指针移动时当前便签及相邻项平滑响应；
3. 标题出现但不遮挡主要内容；
4. 持续悬停约 1 秒显示归档和删除；
5. 单击打开预览且不抢当前应用焦点；
6. 点击编辑后编辑器获得焦点；
7. `Esc` 按层级关闭；
8. 开启“减少动画”后功能完整且无弹性动画。

### AC-03 Dock 拖动与多屏

1. 使用手柄拖动 Dock；
2. 拖动期间便签收拢且快捷操作隐藏；
3. 跨屏释放后吸附最近左右边缘；
4. 垂直位置保持在工作区内；
5. 重启后位置恢复；
6. 拔除显示器后 Dock 回到可见屏；
7. 混合 DPI / Retina 下视觉和命中区一致。

### AC-04 Quick Capture

1. 在其他应用输入时触发快捷键；
2. Capture 出现在鼠标所在屏；
3. 使用中文或日文 IME 输入，并用 `Shift+Enter` 换行；
4. `Enter` 保存；
5. 原应用恢复焦点；
6. 新便签出现在 Dock 顶部；
7. 模拟磁盘满时 Capture 不关闭，内容可复制。

### AC-05 编辑、任务与 Markdown

1. 创建便签并选择任意一种颜色；
2. 输入独立标题和 Markdown 正文；
3. 插入、续建、退出并切换任务；
4. 粘贴富文本后仅保留纯文本；
5. Undo / Redo、IME 与 emoji 均正常；
6. 自动保存状态正确；
7. 预览与原文语义一致；
8. 恶意 HTML 或未知 URL scheme 不执行。

### AC-06 归档、删除与搜索

1. 从快捷操作归档一条便签；
2. Dock 中消失，Archive 中可见；
3. 恢复后回到活动列表；
4. 删除后 10 秒内可撤销；
5. 超时后无法在 Library 中找到；
6. 标题和正文搜索结果正确，日志中无查询内容。

### AC-07 跨平台迁移

1. macOS 导出 `.stickies v2`，Windows 导入；
2. Windows 导出 `.stickies v2`，macOS 导入；
3. 支持字段保持一致；
4. `pinned` 缺失警告明确；
5. 损坏文件和未知高版本安全拒绝；
6. 原文件不被修改；
7. 使用带密码 `.notybackup` 在两平台间恢复完整字段。

### AC-08 更新与恢复

1. 编辑时检测到更新，不强制退出；
2. 用户确认后 flush 并创建备份；
3. 正常 migration 成功；
4. 人为制造 migration 失败后恢复旧数据；
5. 发布者不同、签名错误和版本倒退的包全部拒绝。

## 17. 技术架构决策

### 17.1 已选技术栈

- 桌面容器：**Tauri 2**；
- Web UI：**Vue 3 + TypeScript**；
- 构建工具：Vite；
- 本地核心：Rust；
- 本地数据库：SQLite；
- Rust 数据访问：**SQLx**，使用内嵌 migration 和事务化 Repository；
- 动画：延续原型的 GSAP，仅用于 Dock 和必要的状态过渡；
- 未来账户与同步服务：独立 API 服务 + PostgreSQL。

Vue 负责视图、交互状态和表单；Rust 负责窗口、系统能力、业务用例、持久化、加密、备份和同步基础设施。前端不得直接执行 SQL，也不得持有明文数据密钥。

### 17.2 跨数据库兼容原则

SQLite 与 PostgreSQL 不进行数据库文件或 SQL 语句级互通。未来互通基于以下稳定契约：

1. 共享领域 ID、字段语义、枚举值和时间格式；
2. 通过版本化 API DTO 和同步协议交换数据；
3. 客户端生成 UUIDv7，离线创建不依赖服务器自增 ID；
4. 使用 `revision`、`updatedAt`、`deletedAt` 和稳定 `sortKey` 支持增量同步；
5. 本地 Outbox 记录待上传操作，服务端用幂等键去重；
6. 服务端返回同步 cursor，客户端按 cursor 拉取变更；
7. schema migration 与 API version 分别演进，不共享 DDL；
8. 冲突策略默认采用字段级规则或最后写入胜出，正文并发冲突必须保留副本，不得静默覆盖。

### 17.3 未来账户与同步预留

MVP 不实现账号和联网同步，但首版代码必须保留以下边界：

```text
Vue UI
  → typed application API
Rust Application Services
  → NoteRepository / SettingsRepository / SyncRepository traits
Infrastructure
  → SQLite repositories
  → Keychain / DPAPI
  → Backup
  → Future HTTP Sync Adapter

Future Cloud
  → Auth API
  → Sync API
  → PostgreSQL
  → Object / backup storage（如需要）
```

未来云同步采用**端到端加密（E2EE）**：

- PostgreSQL 仅保存标题/正文密文、nonce、密钥版本和最小同步元数据；
- 解密密钥不上传为服务端可直接使用的明文，正文只在已授权客户端解密；
- 搜索继续在客户端本地完成，MVP 及首版同步不提供服务端正文搜索；
- 账号密码变更不得要求重新加密全部便签，账号认证凭据与内容主密钥分离；
- 正式启用同步前必须完成设备授权、恢复密钥、密钥轮换和设备撤销方案；
- 若未来引入服务端全文搜索或 AI，必须作为隐私模型变更单独立项，不得静默降低 E2EE。

### 17.4 技术 Gate 仍需验证

技术栈已确定，但以下能力仍是开工后的阻断性 Spike：

1. 两平台不抢焦点预览、编辑得焦点与焦点恢复；
2. Windows Alt+Tab / 任务栏和 macOS App Switcher / Dock 控制；
3. 多显示器、混合 DPI、Retina 和热插拔；
4. 中文 / 日文 IME、Undo / Redo、RTL 和可访问性；
5. Dock 高频指针动画 60fps，且视觉与命中区一致；
6. 状态区、全局快捷键、开机启动、Keychain / DPAPI；
7. SQLite migration、备份、签名安装和自动更新；
8. Rust command 的类型生成、错误契约和前后端版本兼容。

详细架构见 `docs/Noty-Technical-Architecture.md`。

## 18. 最终范围结论

Noty Desktop MVP 采用“**跨平台统一产品 + 本地优先数据 + 平台适配窗口能力**”的方向。

`index.html` 已验证的纵向 Dock、距离感应、持续悬停快捷操作、左右拖动吸附、预览卡、独立标题、任务、基础 Markdown、6 色和自动保存反馈，作为正式产品的交互基线。原 Windows PRD 中的托盘、快捷捕获、Library、搜索、迁移、加密、备份、更新、多屏和可靠性要求扩展为 macOS 与 Windows 的共同产品要求。

MVP 不加入云同步。跨平台通用首先意味着：**能力一致、数据可迁移、体验一致、两端可靠发布**，而不是依赖账号实现实时同步。
